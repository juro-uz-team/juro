# Bound complete verified evidence context

Status: accepted

A Provision Set can contain many short operative provisions. Rejecting every set with more than twelve sources discards complete evidence independently of its size. Selecting only twelve can instead remove a material rule, exception or condition.

Selection admits complete sets within a shared budget of 32,000 text characters and an absolute safety ceiling of 24 sources. It never drops an operative provision solely to fit that budget. Candidate assessment receives complete authenticated article text. Explicit article references connect context only within the same revision and language; each assessment includes the complete connected context. Independent sets may be split into batches, while an oversized connected set is unavailable rather than shortened. The chat adapter applies the same budget to the combined context, including both endpoints of a historical comparison.

This replaces the earlier bounded-excerpt assessment decision: retaining only the beginning and end of a provision can hide its operative rule before Requirement Support is determined. An assessment batch has at most eight primary candidates; linked context may bring the complete request to the shared 24-source ceiling. Context alone does not establish support for a candidate. Final selection and claim validation still require authenticated evidence and explicit requirement mappings.

The public answer and gateway source inventories accommodate the same source ceiling. Per-claim citation limits, membership authentication, temporal eligibility, current-source checks and final claim grounding remain unchanged. This is a resource bound, not evidence of adequate coverage: every independent requirement must still have appropriate support.

No source artifact or applied migration changes. Acceptance requires tests for retaining thirteen compact provisions, rejecting oversized complete text, preserving requirement-to-source mappings, and repeated browser inspection. Answer completeness and end-to-end latency remain separate acceptance criteria.
