# JURO Practice

Рабочий модуль `apps/platform`, с PostgreSQL, штатными сессиями JURO, общими
идентификаторами пользователей, пространств, контактов, дел, задач, документов и
файлов. Модуль выключен по умолчанию. Эта ветка не выпускалась на staging или
production; адрес опубликованного пилота не подтверждён.

## Что хранится и работает

- Клиенты — физические и юридические лица, реквизиты, происхождение конкретного
  обращения, настраиваемые воронки, этапы, ответственные, назначения на дела,
  внутренние заметки, сообщения, задачи и шаблоны начала работы.
- Самостоятельная оболочка `/practice?locale=ru|uz|en` и встроенные страницы
  `/{locale}/{accountType}/practice`,
  `/{locale}/business/{workspaceId}/practice` используют одни компоненты и API.
- Фиксированные роли `owner/admin`, `lawyer`, `assistant`, `accountant` расширяют
  существующее членство JURO. Клиент не становится сотрудником пространства.
- Клиент принимает одноразовую ссылку после входа в подтверждённый аккаунт JURO;
  руководитель отдельно проверяет личность и подтверждает связь. Совпадение
  email или имени ничего не объединяет. Отзыв приглашения проверяется на сервере.
- Существующее маркетплейсное дело подключается по исходному ID после явного
  согласия клиента и проверки действующего lawyer grant. Дело остаётся в своём
  пространстве; материалы, сообщения, план и консультация читаются из исходных
  сущностей. Право руководителя фирмы не заменяет исходное разрешение клиента.
- Редактор с абзацами, заголовками, выделением, списками, таблицами и автополями;
  автосохранение, контроль ревизии, сохранение значимых версий. Есть восемь
  стандартных проектов шаблонов в трёх языках и приватные шаблоны фирмы.
- DOCX импортируется с ограничениями, указанными в интерфейсе. Исходный файл
  сохраняется в существующем приватном объектном хранилище после штатного
  карантина и антивирусной проверки. Макросы и активные вложения отклоняются.
- Комментарии, предложения изменений, принятие/отклонение, согласование клиентом,
  фиксация версии, загрузка подписанного PDF и отдельная отметка юриста.
  Согласование, получение подписанного экземпляра и оплата — разные операции.
- PDF и редактируемый DOCX действительно формируются на сервере, включая
  кириллицу, узбекскую латиницу, английский, таблицы и переносы страниц.
- Счета с зафиксированными реквизитами фактического исполнителя и клиента,
  частичные поступления, аванс/переплата, расходы, учёт времени, регулярные счета,
  возвраты и исправления отдельными записями. История выставленных счетов,
  платежей и версий документов не перезаписывается.
- Выбранные записи времени превращаются в позиции одного счёта атомарно;
  повторное выставление по тем же записям блокируется. Счёт можно связать с
  согласованным договором и его этапом. Язык счёта выбирается независимо от UI.
- Денежная арифметика использует целые минимальные единицы и BigInt; курсы —
  PostgreSQL numeric. Отчёты показывают валюты отдельно, а пересчёт использует
  сохранённый с операцией курс. Отсутствующие курсы указаны явно.
- Комиссия начисляется только по настроенному правилу от подтверждённого
  поступления. Сохраняются версия, база, ставка и результат. Исправления и
  возвраты используют исходное правило. Коммерческие ставки не предустановлены.
- CSV/XLSX: серверный предпросмотр, сопоставление столбцов, явная политика дублей,
  построчные ошибки, итог и повторяемый без дублирования запрос. Формулы Excel
  не выполняются. Выгрузка CSV защищена от формул.
- Настройки обзора сохраняются для пары пользователь/пространство. Списки имеют
  поиск и пагинацию; выбор клиента/дела также поддерживает серверный поиск.

## Локальный запуск

Используйте существующую конфигурацию JURO, PostgreSQL и объектное хранилище:

```sh
npm --prefix apps/platform ci
npm --prefix apps/platform run db:migrate
npm --prefix apps/platform run dev
```

Добавьте `PRACTICE_ENABLED=true` в конфигурацию **тестового** окружения и выдайте
доступ конкретному пространству. Обычная регистрация не включает Practice.
Штатный `npm --prefix apps/platform run jobs` уже вызывает фоновые операции
Practice; отдельный scheduler или процесс деплоя не нужен.

Не запускайте это приложение через произвольный `next start`: поддерживаемый
native server дополнительно закрывает старые маршруты, не учитывающие назначения
на дела. Штатные `dev` и `start` используют этот сервер.

На реальных данных миграции `postgres/0059-practice.sql`,
`0060-practice-consultation-sync.sql` и `0061-practice-invoice-language.sql`
применяются через
существующий порядок резервирования и выпуска из
[`docs/deployment/native-environments.md`](../../../../docs/deployment/native-environments.md).
Ранее применённые миграции не изменены. Drizzle-модель находится в
`db/practice-schema.ts`; SQL также содержит триггеры неизменяемых записей.

## Включение, подписки и отключение

Административный API: `/api/platform/admin/practice`, только через существующий
приватный административный контур, staff capability `staff.operations.manage`
и свежую MFA-сессию. Обычный администратор фирмы этого права не получает.
POST требует штатную проверку origin и `X-Juro-Csrf: 1`.

Пример тела выдачи доступа — значения заменяет уполномоченный оператор:

```json
{
  "action": "access",
  "workspaceId": "ws_REPLACE_WITH_EXISTING_WORKSPACE",
  "enabled": true,
  "pilotUntil": "2026-12-01T00:00:00Z",
  "features": { "practice": false },
  "seatLimit": null,
  "reason": "Explicit invitation to the private Practice pilot"
}
```

Дата здесь только пример; она не применяется автоматически. `pilotUntil` —
индивидуальная административная выдача доступа. После пилота запись действующей
подписки читается из существующей `subscriptions`, а её состояние проверяет
`entitlementsForSubscription`. Для платного использования также требуется явно
настроенное разрешение `features.practice=true`. Цен, checkout и новых планов
нет. `seatLimit` остаётся пустым, пока оператор не задаст согласованный лимит.
При принятии приглашения и активации сотрудника лимит проверяется сервером.

`enabled=false` у конкретного пространства или окончание пилота/подписки
оставляет чтение и экспорт, ограничивая изменения. Исключение сотрудника
прекращает его доступ, а не переводит его в режим чтения. Глобальный
`PRACTICE_ENABLED=false` полностью отключает маршруты модуля. Таблицы, документы,
подписанные файлы и счета при этом не удаляются. Для восстановления доступа
достаточно вернуть переключатель и разрешение пространства.

Встроенная ссылка в кабинете появляется только у участника допущенного
пространства. Не нужно переносить данные или менять идентификаторы.

## Интеграционные интерфейсы

| Область | Подключение |
| --- | --- |
| Авторизация | `requireApiUser`, `getSessionUser`, существующие `auth_sessions` |
| Пространства/команда | `workspace_members`, штатные приглашения JURO, `withPracticeSeat` |
| Клиенты/дела/задачи | `contacts`, `cases`, `tasks` плюс таблицы расширения `practice_*` |
| Документы/файлы | `documents`, `document_current_content`, `document_files`, существующий quarantine/scanner и private object store |
| Подписки | `entitlementsForSubscription`, существующая `subscriptions`, административный допуск пилота |
| Уведомления | общая `notifications`, метаданные доставки `practice_notifications`, штатный почтовый транспорт и цикл jobs |
| ИИ | текущие runtime settings, OpenAI adapter JURO, operational flags, circuit breaker, `ai_runs` и общий `ai_usage_ledger` |
| Календарь | OAuth/PKCE, выбранный Google Calendar, синхронизация в штатном jobs; исходные `lawyer_consultations` обновляются по тем же ID, новые встречи собственных клиентов используют общую проверку занятости |
| Будущие платежи/ЭЦП | интерфейсы в `adapters.ts`; работающего провайдера пока нет |

Основной API `/api/practice`: `bootstrap`, `overview`, `cases`, `contacts`,
`tasks`, `documents`, `document`, `templates`, `invoices`, `payments`, `expenses`,
`time`, `recurring`, `events`, `files`, `reports`, `team`, `notifications`.
Исходные данные JURO: `juro-cases`, `materials`, `plan`, `source-files/{id}`,
`export/material/{id}?format=pdf|docx`. Подключение: `case.create` с
`existingCaseId`; сервер проверяет активный grant выбранного ответственного,
его членство в фирме и подтверждённую связь CRM-контакта с владельцем дела.
Происхождение такого дела фиксируется как `juro_marketplace`.
Изменения: POST `commands`; импорт: `imports/preview`, `imports/confirm`;
файлы: `uploads`, `files/{id}`; экспорт:
`export/document/{id}?format=pdf|docx` и `export/invoice/{id}?format=pdf|docx`.
Во всех запросах пространство передаётся как `workspaceId`, но права всегда
определяются сервером. Изменения требуют `Idempotency-Key` и CSRF-заголовки.

Для публикации приватного шаблона руководитель сначала вызывает
`template.publication` с `requested=true`. Staff может опубликовать только эту
разрешённую версию (`publish-template` в административном API). Изменение текста
отменяет пригодность старого разрешения; общий staff-доступ не раскрывает
приватные шаблоны автоматически.

Комиссии задаются действием `commission` административного API: `source`,
`planCode`, `serviceType`, `rateBps`, `active`, `reason`. Каждая настройка создаёт
следующую версию; новые настройки не меняют старые начисления. Собственные
клиенты не получают комиссию без явно созданного правила.

## Внешние настройки и состояния

- **Google:** `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`,
  `PRACTICE_GOOGLE_REDIRECT_URI` (callback `/api/practice/google/callback`) и
  `PRACTICE_GOOGLE_TOKEN_KEY` (32 случайных байта в hex, в secret storage).
  Каждый пользователь самостоятельно проходит OAuth и выбирает календарь.
  Токены шифруются AES-GCM. Обмен минимален: нейтральное название и время,
  без обстоятельств дела. Есть incremental sync, постоянные event IDs, etag,
  конфликты, отзыв доступа и отключение без удаления чужих событий.
- **Почта:** существующие `RESEND_API_KEY`, `EMAIL_FROM`, `EMAIL_DELIVERY_MODE`.
  В тестовом capture-режиме статус — `captured`, а не реальная отправка.
  Отсутствие настройки и ошибки доставки видны в уведомлениях. Содержание дела
  и имена клиентов в тему письма не попадают.
- **ИИ:** существующее подключение провайдера JURO плюс
  `PRACTICE_AI_ALLOWED=true` после проверки политики данных и отдельное разрешение
  владельца пространства. По умолчанию материалы не отправляются. ИИ получает
  только выбранные доступные документы. Результат сохраняется как предложение,
  без изменения карточек. Эта операция не выполняет правовой поиск: источники
  обозначены как непроверенные, ссылки и юридически значимые сроки не выдумываются.
- **Файлы:** действующее приватное хранилище, quarantine и ClamAV JURO.
  Недоступный сканер блокирует приём файла; обход не предусмотрен.

Секреты не размещаются в репозитории. Хостинг, DNS, домены, production-ветка и
GitHub Actions этой работой не изменяются. Cloudflare не используется.

## Проверки

```sh
npm --prefix apps/platform run type-check
npm --prefix apps/platform run build
```

`tests/practice.test.ts` содержит проверки точности, структуры DOCX/PDF, CSV/XLSX
и сквозной сценарий. Интеграционная часть запускается **только** при явном
`PRACTICE_TEST_DATABASE_URL`: адрес должен быть loopback, имя базы —
`juro_practice_verification` или начинаться с `juro_practice_verification_`.
Примените штатные миграции к этой отдельной синтетической базе, затем из
`apps/platform`:

```sh
node --import tsx --import ./tests/helpers/runtime-env.ts --test tests/practice.test.ts
```

В сценарии используются настоящие сессии JURO и PostgreSQL, реальные PDF/DOCX,
проверяются частичная оплата, возврат, исправление, комиссия, повторные запросы,
доступ разных ролей, другая фирма, неназначенный юрист и отзыв клиента. Google
проверяется с тестовыми HTTP-ответами провайдера, почта — через native capture,
сканер — явно обозначенной тестовой реализацией. Это не live-проверка Google,
Resend, ИИ или антивирусных сигнатур.

В среде разработки выполнены три группы проверок:

1. `type-check` и production build платформы прошли; новые миграции применены
   штатным мигратором к изолированному PostgreSQL с синтетическими данными.
2. Сквозной сценарий и проверки файлов/импорта прошли (5 тестов, включая
   вложенные сценарии Google и исходных сущностей JURO). Браузерный проход
   проверил серверную запись из формы, открытие документа, три языка и ширину
   390 px без переполнения или ошибок React.
3. Проверены роли, чужое пространство, закрытый файл, неназначенный юрист,
   отзыв клиента и grant, повторная оплата/комиссия/выставление времени,
   конфликты календаря после утраты назначения. Связанные существующие тесты
   приглашений, маршрутизации, работы юриста и связей документов прошли (19).

Сборка сохраняет предупреждения существующего кода о нескольких lock-файлах
и `import.meta` в `lib/document-comparison/extract.ts`; они не блокируют сборку.

## Доступ через существующий кабинет

Старые общие API кабинета не учитывают назначения Practice. Поддерживаемый native
server закрывает их для текущего допущенного пространства (либо пространства в
явном business-маршруте); ссылка на Practice остаётся доступной. Это действует и
после отключения модуля, чтобы старые API не стали обходом ограничений. В другом,
не подключённом к Practice пространстве штатные инструменты продолжают работать.
Материалы подключённого дела открываются через проверяемый адаптер Practice,
а не через вторую копию документа. Расширение старого редактора и всех общих
экранов до пообъектных назначений в эту ветку не входит.

## Что требуется перед реальным пилотом

- Выполнить обычное ревью и выпуск в существующее тестовое окружение; применить
  добавочные миграции с обычной резервной копией, настроить приватное хранилище
  и работающий сканер, выдать доступ конкретным пространствам через staff API.
- Реальные OAuth, двусторонний обмен с аккаунтом Google, доставка писем,
  обработка ИИ и ClamAV требуют подключения и проверки в выбранном тестовом
  окружении. В рабочем окружении этой разработки доступов к ним не было.
- Шаблоны — проекты. Сложные колонтитулы, рисунки, вложенные таблицы и полная
  совместимость с произвольным форматированием Word не гарантируются.
- Реальная ЭЦП и онлайн-оплата не подключены согласно согласованным исключениям.

Автоматической публикации feature-ветки или подтверждённого публичного адреса
нет. Локальный `/practice` проверяется через штатный native server. Не включайте
модуль всем пользователям: административный допуск должен оставаться адресным.
